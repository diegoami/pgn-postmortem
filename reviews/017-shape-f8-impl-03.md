## Findings

1. **non-blocking — the history's styling isn't placed, and the strip test covers only pages.** The
   Recently viewed list, the marks and the Clear button will need some CSS. Today every page's CSS
   is `assets/style.css` (`build_site` writes `STYLE + piece_css()`), and that file is part of the
   golden set. Two consequences:
   - If the new rules go into `style.css` for every build, the `--no-history` set can no longer
     equal `main`'s. The done-when then fails, or it pushes the implementer into a `style.css` that
     depends on the mode.
   - The strip test "from every page" doesn't cover the stylesheet, so history-only CSS goes
     unchecked, apart from the golden diff in the pull request.

   Suggested, at implementation: put the styling in the history's own markup (a `<style>` inside the
   hidden containers, stripped with them), or add it to `style.css` only with the history and extend
   the strip test to the stylesheet. This doesn't block: either choice meets the scope, and the
   golden diff shows it.

2. **non-blocking — the slot text the second golden set needs isn't listed.** The block says the
   `--no-history` set is "regenerated with its own documented command" (`ROADMAP.md`, done-when
   1). But `CLAUDE.md` lists the generated paths (`tests/golden/site/**`), gives the golden
   regeneration commands ("A change to the page output updates the golden files…"), and has the
   tests row's coverage. All three need the second directory, its command and the strip test. The
   block names only the new gate row and the "three gates" sentence. The builder should update all
   of them in the same change, and the implementation review can check.

3. **non-blocking — the CI wheel step is a check outside the gates table.** A CI step that can go
   red blocks the merge in practice. Gates discipline 1 asks every gate to be declared in one table,
   and the slot will say that only the three gates decide a merge. Suggested: record the step in the
   tests row, under "when" and "CI setup" (the wheel's contents checked on one Python version), or
   give it its own row. Add it, and the `setuptools` pin, to the "proposed, confirmed by the owner's
   merge" list. The command-line option for `site_key` isn't named either (for example
   `--site-key`). That is within *Artistic license*, but worth fixing in the same edit.
